# Predictive Maintenance for Industry Devices
Predictive maintenance is a subject of massive importance in industries. Failure of a machine can completely derail their entire assembly lines and lead to massive losses. An effective solution would be to predict when they might fail, and take preventive measures accordingly to prevent that, usually by performing accurately scheduled maintenance.

As our 3rd year project, we developed a system that would allow us to make these predictions.

## Stage 1 - Machine Learning
In order to predict something, we would need historical accurate data. We found a dataset on Kaggle which would allow us to train our machine learning model on. This machine learning model will help us make these prediction.

## Stage 2 - IoT
In order to get the required data to feed into the model and make the predictions, we would need various sensors. And to get the data from the sensors we would need IoT devices.

The one we decided to go with was the Arduino UNO, which was simple enough for our needs. We were also considering the Raspberry Pi Pico, which is an equal alternative. We chose the Arduino because of its availability for us.

As students, we did not have access nor the budget for the sensors to measure rotation and torque. So we decided to only utilze the temperature sensors and connect it to our Arduino. For the rest of the features, we simulated them by providing a range from where random values will be generated.

We ran the Arduino code through the Arduino IDE and used the software CoolTerm to write the inputs to a csv file `sensor_readings.py`.

This csv file is uploaded to Google Colab, where we input these data (along with the simulated data in our case) and pass them through our ML model. The ML model makes its predictions, and we add the predictions along with the rest of the parameters in another csv file `sensor_data.csv`.

This file would be cleared once the data has been moved to the backend.

## Stage 3 - Backend
We are using a PostgreSQL database to store all the sensor data. The `sensor_data.csv` file is passed through an API POST request which inserts any new entries in the file to the database. The only limitation here is that we didn't make a direct upload mechanism, but we need to keep the csv in the backend directory for this to work.

We built the REST APIs in NodeJS + Express server due to the fast development speed it has. NodeJS also has the `pg` module which makes connecting to our postgreSQL database and making DML/DDL commands very easy.

There is also GET request which fetches all the data. This will be sent to the frontend.

We utilized Postman for testing the API, which was really helpful as the frontend wasn't built yet, and Postman was a significant upgrade over simply using the browser to display the JSON outputs.
## Stage 4 - Frontend
The frontend was built using ReactJS and TypeScript. TailwindCSS for the styling as well. We used `axios` to integrate our frontend and backend so that we could call that API to get the database data.

The main part of the frontend is the dashboard, which displays a chart of the database, with the id as the x-axis and probability of failure as the y-axis. We plan to make timestamps the x-axis instead by modifying the database, but the id is in chronological order so we were able to temporarily make it work for now.

We built the chart using chartJS.

Whenever the probability of failure goes above 70%, we show warnings on the dashboard. We also have a drop down to choose between various machines.
